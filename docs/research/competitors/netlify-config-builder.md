# Competitor research: "Bot Config Builder" (majestic-biscochitos-b7a68b.netlify.app)

Researched 2026-11-16; screenshot pass 2026-11-17 (48 shots, text dumps and a route/section table in `.audit/netlify-config-builder/`). No account, login or payment exists or was needed.

## Summary

- **What it is.** A static, offline-capable web page that builds the configuration for a self-hosted Python GGE bot. It is a config generator, not a hosted bot. The bot itself (a `main.py` with an `EXAMPLE_BOT_CONFIG` dict, plus a `gge_core/` package with `config_service.py` and `data_loaders/unit_names.py`) is not on the site. The page's public `README.md` (served at `/README.md`) describes the files and the build. It says the page "mirrors `gge_core/config_service.py`" and that you can "double-click `index.html`. It runs from your files with no server and no internet."
- **How it runs.** It is all client-side. During the session the page made no requests to any other host and wrote nothing to localStorage. The only extra element is Netlify's "Powered by Netlify" badge iframe. The output is JSON or a Python dict, which the user copies, downloads or pastes into their own bot. The bot runs on the user's machine and logs into GGE with `server_header`, `username` and `password`. The README says the page leaves those login fields out on purpose, to "keep them out of a shared config".
- **Pricing.** None. There is no pricing, billing, login, tiers, docs site, Discord, YouTube or changelog, and the page has no outbound links at all. `/robots.txt`, `/docs`, `/faq` and `/changelog` return 404.
- **Limits built into the schema:** 50 commander slots; Troops picks up to 2 soldiers per castle; Tools picks up to 5 tools per castle; crafting takes up to 2 recipes per building; Glory support tools take at most 3; glory autofill waves go from 1 to 21; the storm farmer keep cap is level 5 and the storehouse cap is level 7; ships go up to level 10.

## How the page works (UI/UX)

- **Header actions:** Load example (asks first: "Replace the current settings with the example from main.py?"), Open file (`.json,.txt,.py`), Paste config (a modal that accepts JSON or the Python dict from `main.py`, with a "Read from clipboard" button; comments and `True`/`False` are accepted; sections missing from the pasted text keep their current values), Copy all, Download, Preview (JSON, or the Python dict for `main.py`), and Reset (back to the bot's defaults).
- **Preview modal:** a JSON / Python (main.py) toggle and a scope dropdown (whole config or one section). The JSON hint reads "Paste this into the bot's config box (Discord /update_config)", so the bot is also configured through a Discord slash command. The page has no Discord link or settings. The Python hint says to paste the dict as the value of `EXAMPLE_BOT_CONFIG` in `main.py`.
- **Config keys:** top level is `global`, `towers_bot`, `forts_bot`, `storm_farmer`, `crafting`, `troops_bot`, `tools_bot`, `hospital_bot`, `berimond_bot`, `glory_bot`. Examples: `active`, `scan_every_x_hours`, `max_daily_attacks`, `reserve_commander` (the Prepared switch), `heal_only_coin`, `tower_40` to `tower_80`, `event_difficulty_name`, `banner_mode`.
- **Per section:** Copy section, Download section and Preview. A section exports as `{ "towers_bot": {...} }` and can be pasted back on its own.
- **Validation:** each nav item has a badge (✓, or the number of issues), and a global status bar shows "Every section is filled in correctly." An alert inside a section lists each problem, for example "Green · Main castle is on but has no soldier picked." or "Green refinery is on but has no recipe." When you paste a config, keys the page does not know are reported and ignored, for example "forts_bot.ice.aggressive_fort is not shown on this page; ignored" (plus `aggressive_fort_min_delay`, `aggressive_fort_max_delay` and "+17 more"). The bot's own validation still makes the final decision.
- **Form controls:**
  - Commander picker: a grid of buttons 1–50. The order in which you switch commanders on becomes their priority, shown as a small number on each button. There is also a "Turn all off" button.
  - Location chips: pick one or more places to send from, plus an "Every castle and outpost you own" option.
  - Time-skip lists: MS1–MS7 in priority order, with up/down/remove controls.
  - Each section's settings stay collapsed until you turn its "bot on" switch on.
  - Upgrade-level dropdowns show the cost of each level in wood/stone or rubies.
  - Searchable unit pickers: names and WOD IDs, for example "Archer #606 Barracks · Soldier". There are 475 soldiers and 464 tools, or 1,011 units with "Show every unit" ticked. The list shows the first 40 matches. A unit outside its list is flagged red, using the same rule as the bot.
  - Light and dark themes.
- The README describes "Tower scan, Fort scan and Attack" as older settings that are hidden from the page but kept so that existing configs still load.

## Gated or unreachable areas

- **The bot itself.** The page only builds config for a Python bot that is not on the site. There is no download link, repo link or contact, so nothing about the bot's runtime could be checked.
- **Hidden keys.** The "+17 more" keys ignored after "Load example" (including `forts_bot.*.aggressive_fort*`) exist in the bot's `main.py` but are not shown on the page. Only the first three were listed. The README also mentions hidden legacy "Tower scan, Fort scan and Attack" sections.
- **Nothing was blocked by login, captcha or payment.** No account was created.

## Method note

There is no account and no server, and the page made no network calls or storage writes. To reveal sections that stay hidden until their "on" switch is enabled, I toggled switches and added placeholder locations in a throwaway headless browser profile. I never pressed Copy, Download or Save, and none of this can reach a game account. I did not read any JS bundles; all findings come from the rendered UI and the public `README.md`.

## Notable for a competitor

1. **Typed, validated config form with paste/round-trip.** The page reads both JSON and Python-dict text, imports per section, keeps unknown keys out with a warning, and shows an issue count on each section. It is a polished way to edit config without a GUI client.
2. **Costs inside the options.** Upgrade-level dropdowns show the wood/stone/ruby cost of each level, and the dethrone cap dropdown lists the ruby cost of every dethrone. This makes spending limits easy to understand.
3. **"Smart skips".** The bot picks skips largest first and pays only for the time above the free speed-up window. Each building and each ship level has its own skip policy.
4. **"Prepared / reserve commander".** A commander is held back so it can hit a fort or storm the moment its cooldown ends.
5. **Commander priority by tap order** across 50 slots, with a separate commander pool for each bot.
6. **Unit catalogue by WOD ID.** It has 1,011 units with names taken from the game's `en.json`, plus a fit check (soldier list vs tool list).
7. **Deep automation for Storm Islands and Berimond.** Resource and troop feeding, hourly transfer caps, per-level storm toggles with "easy only", auto-unlocking Berimond with a chosen camp, and a Berimond castle builder (tents, HQ, training grounds, decorations).
8. **Gaps:** no scheduling windows, no humanization or proxies, no notifications, no multi-account, no dashboard or logs, and no quests, gifts, feasts or Nomad/Samurai/Khan/Underworld-specific bots.
